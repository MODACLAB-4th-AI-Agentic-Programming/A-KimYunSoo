# POM 아티팩트 해결: HeightScale이 높을 때 굴곡이 어색한 문제

---

## 증상

> HeightScale을 높이면 굴곡 있는 부분이 어색하고 이상하게 보인다.

---

## 배경 지식

### POM 레이마칭이란?

POM은 실제 3D 모델을 바꾸지 않고, **픽셀 셰이더에서 UV를 밀어서** 입체감을 흉내낸다.

UV를 얼마나 밀지 계산하기 위해 **레이마칭**을 사용한다.  
카메라에서 표면으로 광선을 쏜 뒤, 조금씩 앞으로 걸어가면서 높이맵과 교차하는 지점을 찾는 방식이다.

```
깊이 0.0  ●──────────────────  시작 (표면 위, h=0.8)
깊이 0.1  ────●───────────────  (h=0.6, 아직 위)
깊이 0.2  ─────────●──────────  (h=0.3, 아직 위)
깊이 0.3  ──────────────●──────  (h=0.1, 통과! 표면 아래)
                        ↑
              0.2~0.3 사이 어딘가에 실제 교차점 존재
              → 이진 탐색으로 8번 더 쪼개서 정밀화
```

이 **"걸어가는 횟수"** 가 바로 레이어 수(`numLayers`)다.

---

## 원인 분석

### 레이어 수가 부족하면 생기는 일

레이어 수가 고정(`64`)인 상태에서 HeightScale만 올리면,  
전체 이동 거리가 늘어나는 만큼 **스텝 하나의 크기**가 커진다.

```
HeightScale 낮을 때 — 64 레이어
● ● ● ● ● ● ● ● ● ● ● ● ● ●   →  촘촘하게 확인

HeightScale 높을 때 — 64 레이어
●     ●     ●     ●     ●       →  드문드문 확인
         ↑
    굴곡을 통째로 건너뜀!
    이진 탐색이 엉뚱한 구간을 정밀화 → 어색한 결과
```

### 왜 레이어를 변수로 늘리면 안 됐나

첫 번째 시도는 HeightScale에 비례해 `numLayers`를 자동으로 늘리는 것이었다.

```hlsl
numLayers *= max(1.0, gHeightScale / 0.05);   // HeightScale이 클수록 레이어 증가

int iNumLayers = (int)numLayers;
for (int i = 0; i < iNumLayers; i++) { ... }  // ← 변수를 루프 상한으로 사용
```

**결과: POM이 완전히 깨짐.**

HLSL에서 루프 안에 텍스처 샘플링이 있으면,  
GPU는 루프를 **컴파일 타임에 몇 번 도는지 알아야** 올바르게 처리한다.  
변수를 루프 상한으로 쓰면 GPU가 루프를 예측하지 못해 오작동한다.

---

## 해결책

복잡한 자동 스케일링 없이, **레이어 범위 자체를 2배로 올리고 루프 상한은 상수로 고정.**

```hlsl
// Before
float numLayers = lerp(64.0, 16.0, saturate(viewDirTS.z));
for (int i = 0; i < 64; i++) { ... }

// After
float numLayers = lerp(128.0, 32.0, saturate(viewDirTS.z));
for (int i = 0; i < 128; i++) { ... }
```

### lerp(128, 32, viewDirTS.z) 의미

카메라 각도에 따라 레이어 수를 자동으로 조절한다.

| 상황 | viewDirTS.z | numLayers |
|---|---|---|
| 정면에서 볼 때 | 1.0 | 32개 |
| 45도 비스듬히 | 0.5 | 80개 |
| 거의 수평으로 | 0.0 | 128개 |

비스듬할수록 레이가 표면을 길게 가로질러서 더 많은 스텝이 필요하기 때문이다.

---

## 결과 요약

| | 수정 전 | 수정 후 |
|---|---|---|
| 레이어 범위 | 16 ~ 64 | 32 ~ 128 |
| 루프 상한 | 64 (상수) | 128 (상수) |
| HeightScale 높을 때 | 굴곡 어색함 | 자연스러움 |
| 변수 루프 상한 | — | 사용 안 함 (드라이버 오작동 방지) |
