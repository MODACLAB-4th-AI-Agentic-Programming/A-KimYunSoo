# 행동 지침

## 1. 코딩 전 충분히 생각하기

**가정하지 말고, 혼란을 숨기지 말고, 트레이드오프를 명시한다.**

구현 전:
- 가정 사항을 명시적으로 밝힌다. 불확실하면 먼저 질문한다.
- 해석이 여러 가지라면 제시하고 선택을 묻는다. 임의로 고르지 않는다.
- 더 단순한 접근법이 있다면 말한다. 필요하면 반론을 제기한다.
- 불명확한 부분이 있으면 멈추고, 무엇이 모호한지 명시한 뒤 질문한다.

## 2. 단순함 우선

**문제를 해결하는 최소한의 코드만 작성한다. 추측성 코드는 금지.**

- 요청 범위를 벗어난 기능은 추가하지 않는다.
- 단일 사용 코드에 추상화를 도입하지 않는다.
- 요청하지 않은 유연성이나 설정 가능성을 추가하지 않는다.
- 발생 불가능한 시나리오에 대한 오류 처리는 작성하지 않는다.
- 200줄로 작성했는데 50줄로 가능하다면 다시 작성한다.

스스로 질문: "시니어 엔지니어가 보면 과하다고 할까?" 그렇다면 단순하게 줄인다.

## 3. 외과적 변경

**반드시 필요한 것만 건드린다. 내가 만든 문제만 정리한다.**

기존 코드 수정 시:
- 인접한 코드, 주석, 포맷을 "개선"하지 않는다.
- 문제없는 코드를 리팩터링하지 않는다.
- 내 방식과 달라도 기존 스타일을 맞춘다.
- 관련 없는 데드 코드를 발견하면 언급만 한다. 삭제하지 않는다.

내 변경으로 생긴 고아 코드는 정리한다:
- 내 변경으로 인해 사용되지 않게 된 import/변수/함수는 제거한다.
- 기존에 있던 데드 코드는 요청 전까지 건드리지 않는다.

기준: 변경된 모든 줄이 사용자의 요청으로 직접 추적 가능해야 한다.

## 4. 목표 기반 실행

**성공 기준을 정의하고, 검증될 때까지 반복한다.**

작업을 검증 가능한 목표로 전환한다:
- "유효성 검사 추가" → "잘못된 입력에 대한 테스트 작성 후 통과시키기"
- "버그 수정" → "버그를 재현하는 테스트 작성 후 통과시키기"
- "X 리팩터링" → "리팩터링 전후 테스트가 모두 통과하는지 확인"

여러 단계 작업은 간략한 계획을 먼저 제시한다:
```
1. [단계] → 검증: [확인 방법]
2. [단계] → 검증: [확인 방법]
3. [단계] → 검증: [확인 방법]
```

# 커밋 규칙

커밋 메시지는 아래 규칙을 반드시 따른다.

## 형식

```
<type>: <한국어 제목>

<상세 구현 내용 (선택)>
```

## Type 목록

| Type | 설명 |
|------|------|
| `feat` | 새로운 기능 추가 |
| `fix` | 버그 수정 |
| `refactor` | 기능 변경 없는 코드 구조 개선 |
| `style` | 코드 포맷, 세미콜론 등 스타일 변경 |
| `docs` | 문서 수정 |
| `chore` | 빌드 설정, 패키지 등 기타 변경 |

## 규칙

- **사용자가 명시적으로 "커밋해줘"라고 요청할 때만 커밋한다. 절대 자동으로 커밋하지 않는다.**
- 제목은 **한국어**로 작성한다.
- 제목은 **명령형**으로 작성한다. (예: "추가하다" → "추가")
- 상세한 구현 내용은 **description(본문)**에 한국어로 작성한다.
- 제목과 본문 사이에 빈 줄을 넣는다.

## 예시

```
feat: 삼각형 렌더링 구현

- 버텍스 버퍼 생성 및 바인딩
- 픽셀/버텍스 셰이더 컴파일
- Draw Call 추가
```

# 프로젝트 정보

## 빌드
- `MSBuild DirectX/DirectX.sln /p:Configuration=Debug /p:Platform=x64 /t:Build /v:minimal`
- MSBuild 경로: `C:\Program Files\Microsoft Visual Studio\2022\Community\MSBuild\Current\Bin\MSBuild.exe`

## 구조
- `DirectX/DirectX/` — C++ 소스 (D3DApp, Sphere, Quad, Camera)
- `DirectX/DirectX/Shader/` — HLSL 셰이더 (POM_VS, POM_PS, Shadow_VS)
- `DirectX/Texture/` — 텍스처 (diffuse, displacement, normal .png)
- `devlog/` — 작업 일지 (YYYY-MM-DD.md)

## 환경
- Windows 11 / Visual Studio 2022 / DirectX 11
- 셰이더는 런타임 컴파일 (D3DCompileFromFile) → .hlsl 수정 후 재빌드 불필요
- 상수 버퍼(cbuffer)는 16바이트 정렬 필수, CPU 구조체와 HLSL 레이아웃 일치시킬 것
